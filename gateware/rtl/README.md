# RTL

Shared Verilog source used by every board. `hermeslite_core.v` (Hermes-Lite boards) and
`radioberry/radioberry_core.v` / `radioberry/juice/radioberry_juice_core.v` (Radioberry boards) are the
top-level cores instantiated by the wrapper file in each variant under
[`../variants/`](../variants/README.md); everything else here is a module they (directly or
transitively) instantiate. `hermeslite_core.v` also holds the `VERSION_MAJOR`/`VERSION_MINOR`
`localparam`s reported to host software — see [`../README.md`](../README.md).

## Subsystems (own README)

- [`ethernet/`](ethernet/README.md) — MAC/IP/UDP/ARP/DHCP/ICMP network stack.
- [`radio_openhpsdr1/`](radio_openhpsdr1/README.md) — CIC/CORDIC DSP receiver and VNA-sweep chains,
  including alternate receiver implementations.
- [`radioberry/`](radioberry/README.md) — Raspberry Pi companion board core (SPI, PIO, and "Juice"
  host-link variants).

## Other subsystems

- **`nco/`** — direct digital synthesizer: `sincos.v` (sin/cos core using `coarserom.v`/`finerom.v`
  lookup tables, generated by `tables.py`), `nco1.v`/`nco2.v` (phase accumulators), `mix1.v`/`mix2.v`/
  `mixtx1.v` (mixers built on the NCO). Used by the receiver chains and by the CW sidetone generator.
- **`localaudio/`** — AK4951 codec I2S interface (`i2s_ak4951.v`) and CW sidetone generator
  (`cw_sidetone.v`), combined in `localaudio.v`; used only by the `_ak4951v3`/`_ak4951v4` variants.
  `mult_s16_s8_s16.v`/`mult_s9_s8_s16.v` and their `.mif`/`.qip` companions are small multiplier/lookup
  primitives for that path.
- **`primitives/`** — vendor-specific hardware primitives: `intel/multipliers.v` (used by every current
  board), `sim/` (simulation stand-ins used by the `../sim/` testbenches), and `efinix/multipliers.v`
  (for a possible future Efinix target — not currently referenced by any board's `files.tcl`).

## Top-level modules

- `hermeslite_core.v` — top-level core for Hermes-Lite boards: wires together the Ethernet stack, the
  openHPSDR protocol packer/unpacker, the receiver/transmit DSP chains, the AD9866 interface, and the
  control/CW/I2C peripherals below.
- `dsopenhpsdr1.v` / `usopenhpsdr1.v` — openHPSDR protocol 1 downstream (PC→radio) unpacker and upstream
  (radio→PC) packer; the wire-protocol core shared with every openHPSDR-descended radio.
- `control.v` — reset sequencing and command-and-control (C&C) register decode.
- `ad9866.v` / `ad9866ctrl.v` / `ad9866pll.v` — AD9866 broadband modem chip data interface, register
  control, and PLL.
- `ethpll.v` — Ethernet clock PLL (Quartus megafunction-generated).
- `fifos.v` — elastic buffering between the sample-rate domains and the Ethernet/host domain.
- `cw_basic.v`, `cw_openhpsdr.v`, `iambic.v` — CW keying: a simple local keyer/sidetone path, the
  openHPSDR host-controlled keyer, and the iambic paddle logic they share.
- `i2c.v`, `i2c_bus2.v`, `i2c_master.v` — I2C master implementations used to configure the AD9866 and
  other on-board devices; `i2c_bus2.v` is the newer command-driven version.
- `hl2link.v` / `hl2link_app.v` — HL2Link, a point-to-point link protocol for synchronizing multiple
  Hermes-Lite radios (e.g. diversity/phased-array setups).
- `slow_adc.v` — periodic readback of the board's slow ADC channels (e.g. temperature/voltage
  monitoring).
- `extamp.v` — external amplifier band-data output (sends an Elecraft `FA` VFO-frequency command over
  UART).
- `exttuner.v` — external ATU control (ICOM AH-4 protocol).
- `led_flash.v`, `debounce.v` — status LED flashing and input debounce.
- `sync.v`, `cdc_sync.v` — clock-domain-crossing synchronizers, carried over from the original HPSDR
  codebase (see the file headers).
- `remote_update.v`, `altera_remote_update_core.v`, `asmi_interface.v`, `asmi_asmi_parallel_0.v` — Intel
  Cyclone remote-update logic, letting the FPGA reconfigure itself from a new image written to flash
  (the mechanism behind the network `.rbf` update path described in
  [`../README.md`](../README.md#loading-gateware-onto-the-radio)).
